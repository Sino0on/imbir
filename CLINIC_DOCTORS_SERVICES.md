# Врачи и услуги клиники — что нового для фронта

Две связанные доработки: клиника теперь может полностью вести карточку своего врача (не только имя/почту при найме), и у процедур появились фото, филиал проведения и собственный график. Всё ниже уже реализовано, залито и живьём протестировано.

---

## 1. Карточка врача

Раньше `POST /api/clinic/doctors/` принимал только имя/почту/телефон, а у уже прикреплённого врача не было вообще никакой ручки, кроме удаления.

**Кто что редактирует.** Всё ниже — зона ответственности клиники. Логин (email/пароль), график приёма и цена консультации сюда не входят — их врач меняет только сам, через `/api/doctor/profile/`. Разделение сделано по смыслу: то, что клиника знает о враче при найме (кадровые/профессиональные данные) — редактируете вы; то, что относится к личному кабинету и записи на приём — нет.

### Эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/clinic/doctors/` | создать и привязать врача — все поля профиля опциональны |
| `GET` | `/api/clinic/doctors/{id}/` | **новое** — полная карточка |
| `PATCH` | `/api/clinic/doctors/{id}/` | **новое** — частичное обновление |
| `DELETE` | `/api/clinic/doctors/{id}/` | открепить (аккаунт врача не удаляется) |
| `GET` | `/api/clinic/doctors/{id}/documents/` | **новое** — список сертификатов |
| `POST` | `/api/clinic/doctors/{id}/documents/` | **новое** — загрузить сертификат |
| `DELETE` | `/api/clinic/doctors/{id}/documents/{doc_id}/` | **новое** — удалить сертификат |

### Поля профиля

**Основная информация**

| Поле | Тип | Описание |
|---|---|---|
| `gender` | string | пол |
| `birth_date` | date, `YYYY-MM-DD` | дата рождения |
| `city` | string | город |
| `languages` | array&lt;string&gt; | языки общения |
| `photo` | файл или URL | фото — как лого клиники, поддерживает и multipart-файл, и строку с URL уже загруженной картинки |

**Профессиональные данные**

| Поле | Тип | Описание |
|---|---|---|
| `primary_specialization_ids` | array&lt;int&gt; | запись; при чтении — `primary_specializations: [{id, name}]` |
| `narrow_specialization_ids` | array&lt;int&gt; | то же для доп. специализации |
| `experience_years` | int | стаж, лет |
| `position` | string | текущая должность |
| `qualification_category` | string | категория/квалификация |
| `academic_degree` | string | научная степень |

**Образование**

| Поле | Тип | Описание |
|---|---|---|
| `education` | array&lt;object&gt; | список записей — см. пример ниже (ВУЗ, год, интернатура, ординатура, специализация по диплому) |
| `additional_education` | array&lt;object&gt; | доп. образование/курсы — `[{name, year}]` |

**Документы**

| Поле | Тип | Описание |
|---|---|---|
| `license_number` | string | номер лицензии |
| `documents` | array, только чтение | сертификаты — грузятся отдельной ручкой, см. выше |

### Пример — `PATCH /api/clinic/doctors/42/`

```json
{
  "position": "Врач-терапевт",
  "qualification_category": "Высшая",
  "academic_degree": "к.м.н.",
  "experience_years": 10,
  "education": [
    {
      "institution": "КГМА",
      "year": 2015,
      "internship": "2016",
      "residency": "2018",
      "diploma_specialization": "Терапия"
    }
  ],
  "additional_education": [
    { "name": "Курс УЗИ-диагностики", "year": 2020 }
  ]
}
```

### Загрузка сертификата — `POST /api/clinic/doctors/42/documents/`

```
multipart/form-data, поле file
либо JSON: {"url": "https://.../уже-загруженный-файл.pdf"}

→ 201
{ "id": 7, "url": "https://.../sertificate.pdf", "uploaded_at": "2026-08-26T07:14:06Z" }
```

## 2. Процедуры: фото, филиал, график

`POST`/`PUT` на процедуре принимал только `name, category, description, price, duration, is_active, doctor_ids`. Добавили три поля с макета и недостающую ручку чтения одной записи.

### Эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/clinic/services/{id}/` | **новое** — раньше карточку редактирования собирали из общего списка |
| `POST` | `/api/clinic/services/` | + `photo`, `branch_id`, `schedule`, `lunch_break` |
| `PUT` | `/api/clinic/services/{id}/` | + те же новые поля |

### Новые поля

| Поле | Тип | Описание |
|---|---|---|
| `photo` | файл или URL | фото процедуры |
| `branch_id` | int | филиал, где проводится процедура — запись; при чтении `branch: {id, name, address}` |
| `schedule` | object | собственный график процедуры по дням недели |
| `lunch_break` | object | `{"from": "13:00", "to": "14:00"}` |

> **О поле «клиника, проводящая процедуру».** На макете это выглядело как отдельное поле «клиника» + «адрес». Так как процедура и так жёстко принадлежит одной клинике, это смэппили на выбор существующего **филиала** той же клиники (у филиала уже есть готовые название и адрес) — поле называется `branch_id`. Если на макете имелся в виду свободный текст адреса, не привязанный к списку филиалов, — дайте знать, переделаем.

### Пример — `POST /api/clinic/services/` (multipart, есть файл)

```
name=Массаж
category=Массаж
price=1500
duration=60
photo=<файл>
branch_id=2
schedule={"monday": {"enabled": true, "from": "10:00", "to": "16:00"}}
lunch_break={"from": "13:00", "to": "14:00"}

→ 201
{
  "id": 1, "name": "Массаж", "category": "Массаж",
  "photo": "https://.../services/photos/proc.jpg",
  "branch": { "id": 2, "name": "Филиал на Чуй", "address": "ул. Чуй 100" },
  "schedule": { "monday": { "enabled": true, "from": "10:00", "to": "16:00" } },
  "lunch_break": { "from": "13:00", "to": "14:00" },
  "...": "остальные поля без изменений"
}
```

> **Важно про `schedule`.** График процедуры сохраняется и отдаётся, но пока **не влияет** на расчёт свободных слотов записи — `/api/doctors/{id}/available-slots/` по-прежнему смотрит только на график врача. Если нужно, чтобы запись реально блокировалась вне графика процедуры — это отдельная задача на логику бронирования, не в этом релизе.

> **`description`** уже принимался и отдавался бэкендом и раньше — менять было нечего, это чисто вопрос добавить поле на форму.
